jcode-bef: StreamBuffer cached character cursor

Outcome: Terminal A candidate retained. The candidate caches remaining Unicode scalar count per queued chunk, eliminating repeated text.chars().count() scans during partial drains and coalescing. It preserves the existing public API and pacing.

Scope and evidence

  • Worktree/branch: agent/jcode-bef-stream-buffer.
  • Owned production file: crates/jcode-tui-core/src/stream_buffer.rs; one focused Unicode regression test added.
  • Baseline and candidate used the same temporary Rust public-path harness, compiled with cargo run --profile selfdev -p jcode-tui-core --example stream_buffer_bench. Harness was removed after each run.
  • Runs used warm-up iterations and wall-clock timing. CPU time, allocator counters, and process RSS/peak memory were unavailable without adding unsupported instrumentation. The public memory profile remained byte-accurate; candidate adds one usize cached count per live queue segment, normally one coalesced segment.

Correctness and runtime validation

  • Focused stream tests: 18 passed, including pacing, max-step ceiling, final flush, ordering, retargeting markers, whitespace behavior, UTF-8 boundaries, and new coalesced multibyte exact-count parity.
  • Complete jcode-tui-core library tests: 63 passed.
  • Public API exercised through jcode_tui_core::StreamBuffer example harness. No built full TUI path was run because this change is confined to the lower public core and the available Rust slot was shared with unrelated workspace checks.
  • Observed unrelated baseline infrastructure warnings: profile package specs for cosmic-text, swash, unicode-linebreak, and zeno do not match workspace packages.

Risk

Low

Rationale: Safe Rust only, no public signature or dependency changes, and all existing focused tests pass. Blast radius: queued stream chunk accounting and partial drain. Mitigation: cached count is updated only on append and partial removal; full removal discards the segment. Rollback: revert the single source commit. Required review action: inspect the invariant that cached count equals text.chars().count().

Medium

Rationale: Queue segments retain an additional usize, increasing per-segment retained state by 8 bytes on this target. Blast radius: fragmented streams with many kind/marker boundaries. Mitigation: existing same-kind coalescing remains unchanged; memory profile and flush behavior are covered. Rollback: revert if fragmentation memory is material in runtime profiling. Required review action: maintainer should check queue-fragment memory against real provider traces.

High

Rationale: This is a hot streaming path and Unicode count drift could alter pacing or drop/duplicate characters. Blast radius: TUI reveal timing and rendered response text. Mitigation: 18 focused tests, Unicode exact-count coverage, and public-path benchmark validation. Rollback: revert the candidate commit without migration. Required review action: Ariel maintainer review is required before merge; do not self-approve or merge.

Recommendation

Retain and push the candidate for maintainer review. It clears the material-gain gate on representative large, fragmented, Unicode, and retargeting workloads. Mark the Bead needs-user-review. No merge performed.
